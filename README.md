# GitBook 미사용 이미지 정리

GitBook 스페이스의 Library에서 **어디에서도 참조하지 않는 이미지**를 AI 에이전트가 효율적으로 찾아 지우는 스킬입니다. GitBook 편집자를 위한 도구입니다.

- **승인한 파일만** Change Request(검토 후 병합하는 변경 묶음) 안에서 삭제합니다.
- **병합은 직접 합니다.** 병합하기 전까지 게시본은 바뀌지 않습니다.
- 삭제한 뒤에는 대상 밖 삭제, 깨진 참조, 게시 본문 변경이 없는지 다시 검사합니다.

## 시작하기

**1. 설치:** 이 저장소를 내려받아 에이전트에서 그 폴더를 열고 요청합니다.

```text
이 저장소의 skill 폴더를 gitbook-library-cleaner 스킬로 설치해 줘. 필요한 패키지도 설치해.
```

에이전트가 파일 쓰기나 패키지 설치의 승인을 요청하면 확인하고 허용합니다. 설치 후에는 새 대화를 시작하고, 스킬이 보이지 않으면 에이전트를 다시 시작합니다.

직접 설치하려면 `skill` 폴더를 아래 위치에 `gitbook-library-cleaner`라는 이름으로 복사합니다. 패키지는 처음 사용할 때 에이전트가 설치합니다.

| 에이전트 | 스킬 폴더 |
|---|---|
| Codex | `~/.agents/skills/` |
| Claude Code | `~/.claude/skills/` |

**2. 요청:** 작업할 폴더에서 에이전트에게 스페이스 주소와 Change Request 번호를 넣어 요청합니다.

```text
GitBook 미사용 이미지 정리해줘. 스페이스는 https://app.gitbook.com/o/…/s/…/ 이고, 삭제는 Change Request #12에서 해. 병합은 하지 마.
```

에이전트가 `gitbook-library-cleaner` 스킬로 진행합니다. 번호 없이 요청하면 삭제하지 않고 본문 기준의 결과만 보고합니다.

## 필요한 것

| 항목 | 조건 |
|---|---|
| 동작환경 | Windows (macOS는 미확인) |
| 에이전트 | Codex 또는 Claude Code. 삭제하려면 브라우저에서 JavaScript를 실행할 수 있어야 합니다. **Codex로 삭제할 때만** 설정의 Browser > Developer mode > Enable full CDP access를 켭니다(적용되지 않으면 Codex 재시작). |
| Node.js | 24 이상 |
| 브라우저 | 에이전트가 조작하는 브라우저(Chrome에서 확인)에서 GitBook에 로그인 |
| GitBook | 대상 스페이스의 편집 권한, 초안 또는 열린 상태의 Change Request |

## 진행 순서

| 단계 | 에이전트 | 내가 할 일 | 바뀌는 것 |
|---|---|---|---|
| 1. 로그인 | 필요한 패키지를 설치하고, 로그인 | 브라우저에서 승인 | 내 컴퓨터에 로그인 정보 저장 |
| 2. 검사 | 삭제 후보의 개수·용량·목록(`candidates.tsv`) 보고 | Change Request 편집을 끝내고 대기 | 내 컴퓨터에 보고서 생성 |
| 3. 승인 | 승인을 기다림 | 목록을 확인하고 전부 또는 일부 승인 | 없음 |
| 4. 삭제와 검증 | 다시 검사한 뒤 묶음으로 삭제하고, 묶음마다 검증 | 브라우저 로그인 유지. 해당 Change Request는 편집·이동하지 않음 | **Change Request의 파일 삭제** |
| 5. 병합 | 결과 보고 | GitBook의 Changes 화면에서 확인하고 직접 병합 | 병합하면 게시본에 반영 |

- 묶음은 50개이며 파일당 약 4~5초 걸립니다. 컴퓨터에서 처음 삭제할 때는 2개로 먼저 시험합니다.
- 보고서는 `gblc-reports/` 폴더에 생깁니다. 문서에서 나온 정보가 들어 있으므로 공유하거나 저장소에 올리지 않습니다.

## 승인 전에 확인할 것

아래 이미지는 쓰고 있거나 쓸 예정이어도 **삭제 후보가 될 수 있습니다.**

- 외부 웹페이지, 메일 등 GitBook 밖에서 주소를 직접 쓰는 이미지
- 내 계정으로 볼 수 없는 스페이스나 다른 조직에서 쓰는 이미지
- 병합이 끝난 과거 버전에서만 쓰던 이미지
- 방금 올려 아직 페이지에 넣지 않은 이미지

삭제 확인 창은 파일 내용이 버전 기록에 남는다고 안내하지만, 복구는 확인하지 않았습니다.

## 로그인

- **에이전트 안에서 합니다.** 다른 앱이나 터미널에서 한 로그인은 보이지 않을 수 있어, 에이전트를 바꾸면 다시 승인해야 할 수 있습니다.
- **권한이 넓습니다.** 브라우저 승인으로 저장되는 권한에는 콘텐츠 쓰기, 병합, 게시, 구성원·권한 변경이 포함됩니다. 이 도구의 스크립트는 조회 요청만 보내고, 삭제는 브라우저 화면에서 합니다.
- Windows에서 `client_id` 오류 탭이 함께 열리면 닫고 다른 탭에서 승인합니다.
- 권한을 조회로 좁히려면 [개발자 설정](https://app.gitbook.com/account/developer)에서 `Read only` 토큰을 만들고, 스킬 폴더의 터미널에서 `node node_modules/@gitbook/cli/cli.js auth`를 실행해 입력합니다. 토큰 방식의 검사는 확인하지 않았습니다. 토큰은 대화에 붙여 넣지 않고, 에이전트에서 로그인이 보이지 않으면 브라우저 승인을 사용합니다.
- 로그아웃은 로그인한 에이전트에게 요청합니다. 터미널에서 로그인했다면 같은 폴더에서 `node node_modules/@gitbook/cli/cli.js logout`을 실행합니다.

## 중간에 멈췄을 때

| 안내 | 할 일 |
|---|---|
| 로그인 필요 | 에이전트에게 로그인을 맡기고 브라우저에서 승인 |
| 검사 불완전 | 편집이 끝난 뒤 다시 검사 |
| 호출 제한, 삭제 묶음을 만들지 않았습니다 | 안내된 시각 뒤에 다시 실행. 검사할 때마다 문서 수 이상의 API 요청을 씁니다 |
| 삭제 스크립트 중단 | 화면에서 직접 이어 지우지 말고 에이전트의 보고를 따름 |
| 검증 실패 | 병합하지 말고 원인(남은 파일, 대상 밖 삭제, 깨진 참조, 본문 변경)을 확인 |

## 판정 기준

검사하는 곳은 다음과 같습니다.

- 대상 스페이스의 본문(숨김 페이지 포함), 페이지 설정과 표지, 재사용 콘텐츠
- 병합되지 않은 모든 Change Request(초안, 열림, 보관)
- 같은 조직의 다른 스페이스와 그 Change Request
- 조직의 사이트 설정(로고, 파비콘, 사이트 안 스페이스별 설정)

| 판정 | 조건 | 삭제 |
|---|---|---|
| 사용 중 | 위에서 파일 ID 또는 업로드 주소가 발견됨 | 안 함 |
| 이미지 아님 | 이미지 형식이 아님 | 안 함 |
| 불확실 | 업로드 주소를 알 수 없음 | 안 함 |
| 삭제 후보 | 위에 해당하지 않는 이미지 | 승인 후 |

- 파일은 이름이 아니라 고유 ID로 구분합니다.
- 본문이 쓰는 이미지는 Change Request에서 교체했어도 남습니다. 병합한 뒤 다시 검사하면 후보가 됩니다.
- 삭제 직전에 누가 참조를 추가하면 삭제 전에는 알 수 없고, 검증에서 발견합니다.

## 개발과 유지보수

GitBook에서 확인한 공식 API와 CLI에는 파일 삭제 기능이 없어, 조회는 API로 하고 삭제는 GitBook 화면의 메뉴를 스크립트가 누릅니다. 에이전트의 절차는 [SKILL.md](skill/SKILL.md), 코드 구조와 확인 방법은 [docs/maintenance.md](docs/maintenance.md)에 있습니다.
