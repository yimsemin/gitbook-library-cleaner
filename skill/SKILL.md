# GitBook 미사용 이미지 정리

검사와 판정은 스크립트가 한다. 에이전트는 스크립트를 실행하고, 요약을 전달하고, 승인받은 삭제를 브라우저에서 실행한다.

## 지킬 것

- 삭제 후보는 스크립트의 결과만 쓴다. 파일명이나 추측으로 대상을 더하지 않는다.
- 사용자가 삭제 목록을 보고 승인하기 전에는 `prepare` 이후 단계를 실행하지 않는다. 승인 ID를 보았다는 것은 승인이 아니다.
- 삭제는 사용자가 지정한 초안 또는 열린 Change Request 안에서만 한다. 병합하지 않는다.
- `검사 불완전`, `중단`, `검증 실패`가 나오면 멈추고 그대로 보고한다. 우회하거나 화면에서 직접 클릭해 대신 삭제하지 않는다.
- `report.json`, `candidates.tsv`, 페이지 본문은 대화에 통째로 읽어 들이지 않는다. 명령의 요약 출력을 쓴다.

## 필요한 것

- Node.js 24 이상, 이 폴더에서 로컬 명령 실행
- GitBook에 로그인한 브라우저를 조작할 수 있고, 페이지에서 JavaScript를 실행할 수 있는 에이전트 도구
- 대상 스페이스의 편집 권한

## 1. 준비 (최초 1회)

이 파일이 있는 폴더에서 실행한다. 이하 `<skill>`은 이 폴더의 경로다.

```sh
npm ci
node scripts/gblc.mjs login
```

`login` 실행 전에 사용자에게 알린다: 승인하면 이 컴퓨터에 콘텐츠 쓰기, 병합, 게시, 권한 변경까지 가능한 로그인 정보가 저장된다. 이 도구는 조회 명령만 실행한다. 승인은 사용자가 브라우저에서 직접 한다. 명령은 승인될 때까지 기다리므로 백그라운드로 실행한다.

권한을 좁히려면 사용자가 [개발자 설정](https://app.gitbook.com/account/developer)에서 읽기 전용(`Read only`) 토큰을 만들어 자신의 터미널에서 `node node_modules/@gitbook/cli/cli.js auth`를 실행하고 붙여 넣는다. 토큰을 대화로 받지 않는다. 로그아웃은 `node node_modules/@gitbook/cli/cli.js logout`.

## 2. 검사 (Dry run)

```sh
node <skill>/scripts/gblc.mjs scan "<스페이스 URL>" --cr <번호>
```

- `--cr` 없이 실행하면 본문 기준으로 보고만 한다. 삭제하려면 `--cr`이 필요하다. 없으면 사용자에게 Change Request 번호를 묻거나 만들어 달라고 한다.
- 결과는 실행한 위치의 `gblc-reports/<시각>/`에 저장된다.
- 검사 대상: 본문과 모든 미병합 Change Request(초안, 열림, 보관)의 페이지(숨김 포함), 재사용 콘텐츠, 페이지 설정, 같은 조직의 다른 스페이스, 사이트 설정.
- 파일 ID나 업로드 주소가 어느 원문에든 있으면 "사용 중"으로 본다. 이미지가 아닌 파일은 삭제하지 않는다.

사용자에게 후보 개수, 용량, `candidates.tsv` 경로, 아래 한계를 알리고 승인을 받는다.

- GitBook 밖(외부 웹페이지, 메일 등)에서 이미지 주소를 직접 쓰는 경우는 알 수 없다.
- 로그인 계정이 볼 수 없는 스페이스와 다른 조직의 참조는 검사하지 못한다.
- 병합이 끝난 과거 버전에서만 쓰던 이미지는 후보가 된다.
- 방금 올려 아직 페이지에 넣지 않은 이미지도 후보가 된다. Change Request를 편집 중이면 끝난 뒤에 검사한다.

## 3. 삭제

`prepare`는 첫 묶음에만 실행하며, `--batch`로 정한 크기는 이후 묶음에도 적용된다. 이 컴퓨터에서 처음 삭제한다면 `--batch 2`로 한 묶음을 삭제하고 `--next` 없이 검증한 뒤, `--batch 20`으로 `prepare`를 다시 실행한다.

```sh
node <skill>/scripts/gblc.mjs prepare --report <report.json> --approve <승인 ID> --batch 20
```

`prepare`는 전체를 다시 검사하고, 승인 후 참조가 생긴 파일이 있으면 중단한다. 일부만 승인받았다면 `--only <파일ID,파일ID>`를 붙인다. 스크립트와 `pending.json`은 보고서 폴더에 저장된다.

브라우저에서:

1. 출력된 Change Request의 **Editor** 화면을 열고 왼쪽 **Library > Images**로 들어가 **목록 보기**로 바꾼다. 화면 언어는 영어여야 한다.
2. 첫 묶음은 `delete.js`의 내용을 그대로 페이지에서 실행한다. 같은 페이지에서 이어지는 묶음은 `next.js`의 내용만 실행한다. `not installed`가 나오면(페이지를 새로 연 경우 등) `delete.js`를 실행한다. 그 밖에 `started: N files`가 아니면 중단한다.
3. 아래 식을 실행한다. 최대 30초를 기다린 뒤 상태를 돌려주므로 `running`이면 같은 식을 다시 실행한다. `stopped`면 오류를 보고하고 멈춘다. 20개 묶음은 80초 안팎이 걸린다.

```js
await (async () => {
  for (let i = 0; i < 30 && window.__gblc.state === 'running'; i++) await new Promise((r) => setTimeout(r, 1000));
  const s = window.__gblc;
  return `${s.state} ${s.done.length}/${s.total} ${s.error ?? ''}`;
})()
```

화면 캡처는 실패했을 때만 한다. 삭제 중에는 페이지를 이동하지 않는다. `stopped` 뒤에 다시 실행하려면 페이지를 새로 고쳐 열린 메뉴를 닫고, `--next` 없이 4단계 검증으로 삭제된 파일을 확인한다. 이때는 남은 파일 때문에 `검증 실패`가 나온다. `대상 밖 삭제`와 `깨진 참조`가 `없음`, `본문(게시 기준) 변경`이 `없음`이고 `재검사 불완전`이 없을 때만 `prepare`부터 다시 한다.

## 4. 검증과 다음 묶음

삭제 스크립트가 끝나면(중간에 멈춘 경우에도) 실행한다. 정상 종료면 `--next`를 붙인다.

```sh
node <skill>/scripts/gblc.mjs verify --pending <pending.json> --next
```

API 반영에 1분 안팎이 걸려 명령이 기다린다. `검증 통과`면 같은 검사 결과로 다음 묶음이 준비되므로 `prepare` 없이 3단계의 브라우저 실행을 반복한다. `삭제할 파일이 남아 있지 않습니다`가 나오면 끝이다. 다음 묶음의 스크립트는 만든 직후에 실행한다. 시간이 지났거나 그 사이 편집이 있었으면 `prepare`를 다시 실행한다.

## 5. 보고

삭제한 개수와 용량, 검증 결과, 남은 파일을 알리고, Change Request의 Changes 화면에서 확인한 뒤 병합은 사용자가 직접 하라고 안내한다. 삭제한 파일의 내용은 GitBook 버전 기록에 남는다고 삭제 확인 창에 안내되지만, 이 도구로 복구해 본 적은 없다.
